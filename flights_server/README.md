# flights_server — 航空データ・バックエンド（1/f「フライト ライブビュー」用）

1/f のシーン **「フライト ライブビュー」（英: Flight Live View）** のためのバックエンド。
**adsb.lol（ODbL 1.0）をサーバ単位で集約**し、全クライアントへ配信する。
クライアント（1/f のシーン）が増えても外部APIへの負荷は一定に保つ。

> ライセンス: コードは **MPL-2.0**。配信する派生DB（航跡・ルート索引・
> オートコンプリート）は **ODbL 1.0** で公開する（adsb.lol 由来のみ）。
> UI には全オープン源のクレジットを常設する。本書は法的助言ではない。

## マイルストーン進捗
- **M1（実装済み）**: 共有レートリミッタ ＋ ラウンドロビン・ポーラー ＋
  正規化 ＋ メモリキャッシュ。外部呼び出しは「周期ごとに1回・1bboxずつ・
  上限(req/s)厳守」。REST/WS は M2。

## 設計の要点
- **外部周期**（`EXTERNAL_POLL_PERIOD_MS`、既定10s）＝この間隔ごとに *1回だけ*
  外部APIを叩き、アクティブな bbox を *1つずつ順送り* で更新する。
  → 各 bbox の実効更新頻度 = 周期 × アクティブ bbox 数。
- **外部レート絶対上限**（`MAX_EXTERNAL_RPS`、既定1）＝レートリミッタが
  最小間隔を強制。周期を短くしても、ここを絶対に超えない（adsb.lol 規約遵守）。
- adsb.lol は**全機体スナップショット（非フィーダー）が無い**ため、ビューポート
  bbox を内包円にして円取得 `/v2/lat/{lat}/lon/{lon}/dist/{nm}` → bbox で絞り込む。
  半径は v2 上限に合わせ最大 250NM にクランプ。
- 失敗/429 は指数バックオフ。失敗時は直近キャッシュを維持。

## 必要環境
- Node.js 20 以上。

## 実行（M1 デモ）
```bash
cd flights_server
cp .env.example .env          # 必要なら値を調整
npm install
npm start                      # = node --env-file 相当で src/index.ts を起動
# もしくは: node --env-file=.env --import tsx src/index.ts
```
関東の bbox を1つ登録し、ポーラーが adsb.lol を叩いて正規化→キャッシュする
様子をログ出力する。

## テスト（ネットワーク不要・ロジック検証）
```bash
npm test
```
正規化・bbox判定（経度180跨ぎ）・円変換クランプ・レート間隔厳守・
ラウンドロビン順送り を検証する。

`.env.example` 参照。秘密情報は置かない（外部キー不要）。
